# 用户偏好与反馈准则（从全部沟通记录提炼）

这些规则来自用户的原话和反复纠正，优先级高于你自己的审美判断。下面列出原话，方便判断边界。

## 沟通方式
- **全程用中文回复**。报告要短、直接：说做了什么、怎么验证的、哪些没验证。
- **有不止一种理解时先问，再动手。**用户原话：「如果你有不理解的先询问我，记住」「如果你拿不准先询问我」。这个项目里最贵的错误，都是自己挑了一种理解直接做：把「中间卡住」做成硬停，把「自动吸附」做成自由滚动加吸附。不确定的时候，用 AskUserQuestion 把每种理解写成选项让用户选。
- 用户说「继续」「开始」「Continue」，就是照上一步定好的计划接着做，不用再确认。
- 用户发截图时，通常只附一句很短的话（如「模型的底下有点奇怪」「位置有点奇怪」）。自己找出原因，用前后对比截图证明修好了。
- 用户说「讨论一下」「计划一下」「我们来讨论」时，先给方案和选项，等用户拍板再做。
- 用户愿意让你按自己的审美做决定（「按你的想法来」「抛弃我的审美」），但前提是方向已经定了。

## 审美方向（不能违背）
- **炫技优先，几乎零文案**：「我只需要炫技，绚丽的特效，炫酷的效果，华丽的动画。指引着可以悬停鼠标进入游戏。我们通过游戏最后聚在一起」。
- 文案要么没有，要么极短。用户否掉过「一个黑盒三种玩法」（「太拉了」）、玩家口吻标语、大标题。每次加文字，都会被要求删。
- 参考对象：igloo.inc（出场方式、粒子用法、呼吸感、写实环境）、activetheory.net（滚动效果）、awwwards 上的 igloo-inc 页面。
- **元素要少，不要乱**（「元素过乱」）：已经删掉的有滚动提示、鼠标拖尾、悬停信标、右侧章节号、左下角章节名、角标、3D 文字「悬停 1s」。不要加回来。
- 风格要统一：三个游戏要是同一种玩具低多边形风格（第一关因此重做成横版纸板小游戏）。展示场景和游戏内部要像同一个世界。
- 要写实、要有质感：月面写实，阴影齐全（「有些光影是不是没有加入阴影，看起来不够立体」）。
- 不喜欢的东西：冰冻效果（「很丑」）、白色颗粒化、突兀的粒子模型、远处拉近看到世界的轮廓和四周的空荡、页面和游戏之间的割裂。

## 交互与手感
- 开屏「直接到位，不要缓慢干预」，但线框和扫描要保留。
- 滚动：**一滑一段，自动到位，中途不停，三个游戏页必停，停下后下一次滑动立即继续，要跟手，不能延迟**。中间过渡不能太快（约 2.9s 合适）。往上滚也是一段一段走。
- 进入游戏：显眼的「[ 进入 ↗ ]」按钮，加上悬停 1s 进入，两种都保留。悬停时长是 1 秒（原来 2 秒，用户要求改的）。
- 进出游戏要无缝衔接，不能出现不相干的画面，不能黑屏，不能卡顿。
- 第三关所有东西都能撞散。

## 性能与工程
- **不要自动降低特效**，桌面永远极致画质。
- 三个游戏按需加载，退出即释放（「如果游戏退出来了，就关掉游戏的进程」）。
- 不用 CDN，不用 npm，不加构建步骤。
- 没用到的文件要清理（已经从 46MB 清到 9.3MB）。
- 每完成一个阶段就 git 提交（「现在保存一个 git 进行下一步」）。部署要等用户点头；当前约定是第 5 条做完再一起部署。
- 声音默认开、不提供关闭选项。

## 素材
- 第 5 条：加 3D 元素、减少代码拼出来的东西（参考 Pinterest 搜「3D」的风格）。要「更精致的」模型。**吉普留着**。展台上的星舰、周围布景、游戏内部场景都要换。
- 配色不一定要石墨黑加冰蓝，黑盒 logo 也可以改，只要找到合适的。
- 只用 CC0 素材（Kenney / Quaternius / Poly Pizza 等），保留 credits。先出 2–3 套风格对比给用户选，**选定后再全站替换**。
